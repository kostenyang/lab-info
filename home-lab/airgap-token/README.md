# Air-gap Token Bridge — 氣隙端 registration token 帶出流程

適用情境:客戶站點**檔案不得帶出、內容允許帶出**,需要把 VCF 9.1 的
`*.registration`(JWT/RS256)token 帶到聯網環境,代客戶到 Broadcom 授權入口註冊。

## 檔案

| 檔案 | 放哪 | 用途 |
|---|---|---|
| `token-qr.html` | 氣隙端 + 聯網端 | 單一離線 HTML(零外連,內嵌 qrcode-generator 1.4.4 MIT)。①切 QR ②重組+驗簽 |
| `verify-token.mjs` | 聯網端 | Node 18+ 零依賴第二道驗簽:`node verify-token.mjs <file>` |

## 先判斷走哪條路

| 現場限制 | 路徑 |
|---|---|
| **文字可以複製貼出**(跳板機剪貼簿、只擋附件不擋文字的管道) | **D. 直接貼文字**(最簡單,先試這條) |
| 可拍照 | **A. QR 螢幕掃描** |
| 不可拍照,但**紙本可帶出** | **B. QR 印在紙上帶出**,到站外再掃(拍照發生在站外) |
| 不可拍照,紙本也不可帶出 | **C. 人工轉抄**(逐行 CRC 校驗) |

## D:直接貼文字

1. 氣隙端把 `.registration` 用記事本開,全選複製(整串是一行、無空格)。
2. 貼到聯網端任何地方(記事本 / 聊天 / 工單皆可,被自動換行沒關係)。
3. 聯網端開 `token-qr.html` → ②還原 → 貼上 → 重組並驗簽 → `✅` 即可下載成 `.registration`。
   或 `node verify-token.mjs pasted.txt`。
4. 貼上常見損壞:中間被截斷、`_`/`-` 被換成別的符號、多了看不見的字元 —— 簽章驗證全部抓得到。

## A / B:QR

1. **氣隙端**:瀏覽器開 `token-qr.html` → ①匯出 → 貼 token → 產生 QR(預設 400 字/張,約 5 張)。
   B 路徑按「列印此頁」印出。記下畫面上的指紋(長度 / 頭尾 10 字 / SHA-256)。
2. **手機**掃每一張 QR(內建相機或任何 QR app),文字轉到聯網電腦(順序不拘、重複無妨)。
3. **聯網端**:同一個 HTML → ②還原 → 貼所有片段 → 重組並驗簽。
   - `✅ RS256 簽章驗證通過` = 與原始 token **逐位元一致**,可直接上傳。
   - 缺片段 / 抄錯字 會明確指出哪一張要重掃。
4. 下載為 `.registration` 或複製 token → Broadcom Support Portal 上傳換 license。
5. 用 `verify-token.mjs` 再驗一次(可選)。

## C:人工轉抄(不能拍照、紙本也不能帶出)

1. **氣隙端**:①匯出 → 貼 token → 「產生轉抄表」。每行 32 字、4 字一組、行末 `|XXXX` 為該行 CRC-16;
   易混字有顏色標示(數字 0 紅底線 / 大寫 O 紅框;數字 1 藍底線 / 小寫 l 藍框 / 大寫 I 藍底)。
2. 逐行抄到你自己的裝置(筆電、手機記事本、或紙上)。**建議連校驗碼一起抄**,
   多 4 字換來聯網端自動逐行比對;不抄也行,聯網端會算出每行 CRC 讓你對照。
   1662 字 = 52 行,兩人一讀一打約 30–40 分鐘。
3. **聯網端**:②還原 → 貼上(行號、空格、校驗碼有沒有都可以)→ 重組並驗簽。
   - 錯的行會**紅字標出行號**,只改那一行再按一次。
   - 全部 ✓ 後再看簽章:`✅` 才算完成。
4. `verify-token.mjs` 也吃轉抄表格式:`node verify-token.mjs typed.txt`。

## 注意

- 驗簽用 token header 內嵌的 JWK 公鑰,實測(2026-09-04)可驗;改任一字元即失敗。
- 瀏覽器驗簽需 WebCrypto(secure context):**用 `file://` 直接開即可**;若嵌在 data: 或某些預覽器會顯示「無 WebCrypto」,改用 `verify-token.mjs`。
- QR 掃不到 → 把「每張字元數」調小。實測 400 / 600 / 900 都可解碼,螢幕拍照建議 ≤ 400。
- 進場前確認客戶**攝影政策**(很多高安全站點連拍照都禁)。
- token 含內部 FQDN / 資產 UUID,雖非機密憑證,仍屬客戶內部資訊,帶出後妥善保管。
- created_on 是 token 產生時間,授權入口可能對過期 token 拒絕,盡量當天帶出當天註冊。
